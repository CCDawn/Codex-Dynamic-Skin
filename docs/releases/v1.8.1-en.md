# Codex Dynamic Skin v1.8.1
**English** · [中文](https://github.com/CCDawn/Codex-Dynamic-Skin/blob/v1.8.1/docs/releases/v1.8.1.md)

A cleanup release for wallpaper-only mode: the panel-transparency slider now drives a single surface layer, the UI no longer goes half translucent and half solid, and Windows starts with one Codex window instead of two.

## Changes

- **Panel transparency is a single layer again**: the main content area, sidebar and composer card each carried their own translucent fill, stacking to roughly 0.93 in the densest spots, so the wallpaper barely showed and the slider made no visible difference. Only the window root keeps a fill now; every other surface steps aside, and the whole window follows the slider.
- **The slider no longer snaps back**: with no stored preference the manager forced the slider back to 30, which maps to exactly the same density as the default, so every drag looked dead. Now only a genuinely stored value is written back, and a drag takes effect immediately without restarting Codex.
- **Sidebar and icon rail unified**: the icon rail, session navigation and main content each kept a white fill, which read as isolated white bands against a translucent window. They now share the single panel density.
- **Cards and composer keep their edges**: with the fills cleared, cards lost the 0.5px shadow ring that used to mark their boundaries. Cards, composer and resource panels now use a fixed light tint plus a hairline border, so they stay legible and layered over the wallpaper; the composer gets its 16px radius back.
- **User messages stay distinct**: user bubbles keep a fixed light-grey fill and outline instead of blending into assistant content.
- **Single-window launch**: every start used to activate the app package first, detect that the debugging argument had been rewritten, close that process, and launch the real one — always flashing two windows. The manager now launches the validated Store executable directly.
- **Launch failure categories preserved**: a rejected direct launch is still classified as access-denied, argument-loss or endpoint-unavailable, and an argument-loss rollback closes only the process it just started, leaving an already-running Codex untouched.

## Unchanged

- Injection still uses a loopback-only `127.0.0.1` CDP endpoint, never modifies the official package or its signature, and stays fully reversible.
- Theme, image and video wallpaper data directories are unchanged and survive the upgrade.
- macOS behaviour is untouched; the version number follows the release.

## Upgrade and usage

- Users on v1.6.x / v1.7.x / v1.8.0 can install the new package in place.
- If the window still looks stale after upgrading, restart Codex once to load the new stylesheet.
- The panel-transparency slider lives in the manager window and applies immediately; the wallpaper-intensity slider still controls how strongly the wallpaper itself shows through.
