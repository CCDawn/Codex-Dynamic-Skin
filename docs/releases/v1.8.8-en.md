# Codex Dynamic Skin v1.8.8

**English** · [中文](https://github.com/CCDawn/Codex-Dynamic-Skin/blob/v1.8.8/docs/releases/v1.8.8.md)

This release fixes the right-side floating dock (side conversation) panel on Codex 26.1117 not showing the wallpaper through: its shell paints an opaque background with a Tailwind arbitrary class the skin never covered, so in wallpaper-only mode the whole dock read as a solid native slab. The dock now shows the wallpaper like the main thread does, while keeping its left border and text readability.

## Changes

- **The dock shows the wallpaper (wallpaper-only mode)**: root-caused with a read-only DOM measurement on a live 26.1117.4957.0 session — the only opaque painter in the dock region is a container `DIV` carrying the class `bg-[var(--app-shell-panel-background,var(--color-surface))]`. It contains neither a `bg-surface` token nor a CSS module name, so every existing surface-clearing rule (the token family and the catch-all) missed it. A new rule clears that fill by matching the shell's own `app-shell-panel-background` token fragment (a stable semantic fragment, not a hash); the dock's left border lives on an ancestor element and its text tokens stay native, so both are untouched.
- **Full mode gives the dock a real material**: the same pane now uses the themed panel material (`--ds-panel-rgb` / the panel-transparency chain), matching how the composer and dialogs already resolve their fill; interactive controls and overlay containers keep their own paint.
- **Selector contract adds a `floating-dock` anchor** (tier L2, optional): the dock only exists while a side conversation is open, so a miss only degrades diagnostics and never gates structural verification; the CSS consumes the same anchor token, and the contract's provenance record is updated with this live evidence. Older Codex builds never render the class, so the rule is inert there and cannot touch elements from the `bg-surface` token family.
- **Both platforms in sync**: macOS reuses the same CSS and contract (the macOS dock DOM was not live-tested; noted in the provenance record).

## Unchanged

- Injection still binds only to `127.0.0.1` loopback CDP; the official install and signatures are untouched.
- The wallpaper-only contract stays as it was: one frosted layer on `#root`, panes and cards transparent, dialogs and menus keeping their near-solid readable fill.
- Local data directories for themes, images, and video wallpapers are unchanged and survive the upgrade.

## Upgrade

- Users on v1.8.0 – v1.8.7 can upgrade in place with the new installer.
- After upgrading, click "Start / Re-apply" once in the manager to restore the full effect; an already open side conversation picks up the new CSS.
