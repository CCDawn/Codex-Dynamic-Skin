# Codex Dynamic Wallpaper v1.7.1

[中文](https://github.com/CCDawn/Codex-Dynamic-Skin/blob/v1.7.1/docs/releases/v1.7.1.md) · **English**

The first release after merging upstream Codex Dream Skin v1.5.19–v1.5.20, absorbing both compatibility and features: Codex 26.930 compatibility, theme transparency controls, the native theme manager, and CODEX_HOME support all arrive in this fork, while video wallpapers, the RDP static-frame fallback, and the Codex Dynamic Wallpaper branding are preserved.

## New features

- **Codex 26.930 compatibility (macOS / Windows)**: Page enumeration now filters by the active page and skips cached pages under the new routing (`[data-app-shell-active-page=false]`), fixing anchor mis-selection that applied the skin to the wrong page. Also adapts cached pages, the title bar, tool pages, code blocks, and expanded tables in 26.930 (upstream v1.5.19 changes; see the platform CHANGELOGs for details).
- **Theme transparency controls (macOS / Windows)**: Background transparency follows "user setting > explicit author alpha > default 30%". macOS adds a per-theme transparency slider and "Follow theme" in the theme menu; Windows offers the same per-theme preference in the native manager window.
- **Native theme manager (Windows)**: Double-clicking the desktop shortcut, the Start Menu entry, or the tray icon opens the same native C# manager window: adjust per-theme transparency (0–100%), restore "Follow theme", and move an unused saved theme to the Recycle Bin after confirmation. The active theme must be switched from the tray first. The previous PowerShell theme-selection window is removed.
- **CODEX_HOME custom directory (Windows)**: Installation, startup, and restore now follow an existing `CODEX_HOME`, falling back to the default `.codex` directory when unset or empty. Backups are bound to their source directory and cannot be restored into a different home; invalid paths produce an explicit error.

## Fixes and improvements

- **Manager EXE start/restore failure (Windows)**: The v1.6.2 manager EXE embedded runtime was missing four files, so Start/Restore failed on clean machines. The Manager EXE asset was hot-fixed during v1.6.2; from this release the embedded manifest is guarded by a contract test.
- **Rendering performance (macOS / Windows)**: Structure checks for skin CSS are cached and refreshed in bulk when the page structure changes, reducing full-page style recalculation while scrolling and switching pages.

## Upgrading and usage

- Users on v1.6.x can upgrade in place by running the new installer; saved themes, images, and video wallpapers are all preserved.
- When using a custom `CODEX_HOME` on Windows, the installer, tray, and the official Codex app must all see the same existing user-level variable. A variable set only in a terminal may not reach apps activated through Microsoft Store; sign out and back in if needed. With an existing backup, restore in the original home before switching directories.
- To try the native theme manager on Windows, double-click the desktop shortcut or the tray icon. On macOS, use the transparency slider and "Delete saved theme" in the theme menu.

## Internal

- Merged all upstream Codex Dream Skin v1.5.19–v1.5.20 changes; the fork's video wallpapers, RDP static-frame fallback, and branding are fully preserved.
- The CI version-consistency gate now covers a seventh version source (the manager csproj); all seven must match before merge and release.
- Release notes are now maintained as paired Chinese/English files (see docs/releases/README.md); the release workflow verifies both exist and are non-empty before publishing.
